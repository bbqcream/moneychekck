# 페이플랜

앞으로 들어올 월급과 지원금을 바탕으로 돈 계획을 적고, 각 항목을 처리한 뒤 남는 돈을 확인하는 앱입니다.

## 실행

Node.js 22.13 이상과 pnpm 11이 필요합니다.

~~~sh
pnpm install
pnpm dev
~~~

[로컬 앱](http://localhost:3000)에서 **새 시나리오**를 만들거나 **예시로 시작**을 선택하세요. 입금을 추가하고, 입금 아래에 지출·저축·투자·상환·송금 항목을 작성할 수 있습니다. 시나리오 하나를 비교 화면의 양쪽에 선택하면 확실한 돈만 넣었을 때와 전체 입금을 넣었을 때를 비교할 수 있습니다.

## 모바일 우선순위

| 우선순위 | 목표 | 상태 |
| --- | --- | --- |
| P1 | 같은 네트워크의 폰에서 입력·비교, 월 고정지출, JSON 불러오기·내보내기 | 구현 |
| P2 | 기존 Vercel HTTPS 주소에서 로그인하고 폰·PC 동기화, 홈 화면 바로가기 | 로그인·동기화 구현, 배포 설정 필요 |
| P3 | 오프라인 재실행과 토스뱅크 현재 잔고 표시 | 오프라인 재실행 계획, 실잔고 조회는 오픈뱅킹 이용 승인 필요 |

### 같은 네트워크의 폰에서 열기

1. PC와 폰을 같은 공유기에 연결합니다. PC는 유선으로 연결해도 됩니다.
2. Windows에서는 ipconfig로 PC의 로컬 IPv4 주소를 확인합니다.
3. 아래 예시의 IP를 PC 주소로 바꿔 실행하고, 폰의 Safari 또는 Chrome에서 같은 IP와 포트로 접속합니다.

~~~sh
pnpm dev --hostname 192.168.0.10 --port 3101
~~~

[접속 주소 예시](http://192.168.0.10:3101)

PC에서 개발 서버를 실행하는 동안 폰에서 접속할 수 있습니다. 입력한 데이터는 접속한 주소와 브라우저별로 따로 저장됩니다. 내부망 HTTP에서 자동 복사를 지원하지 않는 브라우저는 텍스트를 선택해 기기의 복사 메뉴로 복사할 수 있게 합니다.

## 구현 계획

1. 계산 엔진에서 금액을 원 단위 정수로 변환하고, 입금과 항목을 순서대로 처리해 잔액 범위를 계산합니다. AGENTS.md의 96만원 예제로 각 단계의 잔액을 검증합니다.
2. 시나리오 목록과 편집 타임라인을 만들고, 입력과 수정 내용을 Zustand를 통해 브라우저 저장소에 저장합니다.
3. 근무수당 계산기와 시나리오 비교를 연결하고, 아이폰 메모 복사용 평문과 전체 JSON 백업을 제공합니다.
4. 타입 검사와 린트, 테스트를 통과한 정적 빌드를 Vercel에서 배포할 수 있게 준비합니다.

## 계산과 저장

- 잔액은 좋은 경우에서 나쁜 경우 순으로 표시합니다. 나쁜 경우 잔액이 음수이면 **모자람**을 표시합니다.
- 반복 항목은 하루 또는 한 달 금액에 입력한 일수나 개월 수를 곱해, 지정한 입금 아래에서 한 번에 계산합니다.
- 월 고정지출은 시나리오에서 적용 시작월과 금액 변경월을 지정합니다. 시나리오에 날짜가 있는 입금이 있는 달마다 한 번 계산하며, 그달 첫 확실한 입금이 있으면 그 입금에 연결합니다.
- 근무수당 계산기는 한국 공휴일과 주말을 제외합니다. 포함된 공휴일 데이터는 2018~2027년이며, 다른 연도를 선택하면 근무일수를 확인하라는 안내를 표시합니다.
- 세금은 기본적으로 적용하지 않습니다. 세금 옵션을 켜면 시나리오의 각 입금액에 적용하고 세액의 원 미만은 버립니다.
- 로컬 모드의 데이터는 현재 브라우저의 localStorage에 저장합니다. 목록의 **전체 JSON 내보내기**와 **JSON 불러오기**로 백업을 주고받을 수 있습니다.

## 온라인 로그인과 기기 간 동기화

1. Supabase 프로젝트에 [계정별 저장 마이그레이션](supabase/migrations/20261120000000_create_payplan_documents.sql)을 적용합니다.
2. 단독 사용이라면 Supabase Authentication 설정에서 공개 가입을 끄고, Users에서 자동 확인된 사용자를 만듭니다. 이메일은 소문자 로그인 아이디 뒤에 **@payplan.example.com**을 붙입니다. 예를 들어 **myplan**의 이메일은 **myplan@payplan.example.com**입니다. Supabase에 설정한 비밀번호를 로그인 화면에서 사용합니다.
3. 기존 Vercel 프로젝트에 **NEXT_PUBLIC_SUPABASE_URL**과 **NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY**를 설정한 뒤 재배포합니다. 로컬에서 온라인 모드를 확인할 때는 같은 두 값을 .env.local에 넣고 개발 서버를 다시 시작합니다.
4. 로그인한 뒤 이미 이 주소에 저장한 시나리오는 **기존 브라우저 계획 가져오기**로 등록할 수 있습니다. 별도로 받은 계획 파일은 **JSON 불러오기**로 추가합니다.

Supabase Auth로 로그인하고 PostgreSQL 행 수준 보안으로 계정마다 문서를 분리합니다. 앱은 설정된 경우에만 Supabase를 사용합니다. 다른 기기에 변경을 저장하고 나서 앱으로 돌아오거나 **동기화**를 누르면 최신 값을 가져옵니다. 동시에 수정해 충돌이 나면 이 탭의 변경을 JSON으로 저장하고 **서버 버전 불러오기**로 최신 값을 선택할 수 있습니다.

## 검증과 배포

~~~sh
pnpm typecheck
pnpm lint
pnpm test
pnpm build
~~~

pnpm build는 out/에 정적 파일을 생성합니다. Vercel은 vercel.json의 Output Directory 설정에 따라 out/을 배포합니다. 이전 커밋에서 STATIC_BUILD_NO_OUT_DIR 오류가 발생하면 이 설정이 포함된 새 커밋으로 배포하거나, Vercel 프로젝트의 Build & Development Settings에서 Output Directory를 out으로 지정합니다.

목록, 편집, 비교 화면은 URL 해시를 사용해, 앱을 한 번 열면 브라우저 안에서 화면을 이동하고 계산할 수 있습니다.

## 토스뱅크 현재 잔고 연동 검토

토스뱅크는 금융결제원 오픈뱅킹 참가기관입니다. 실계좌 잔고를 조회하려면 앱 운영자가 금융결제원과 이용계약을 체결하고 승인을 받은 뒤 사용자의 계좌 등록 동의를 받아야 합니다. [금융결제원 오픈뱅킹 안내](https://openapi.kftc.or.kr/service/openBanking) · [잔액조회 API](https://developers.kftc.or.kr/dev/openapi/open-banking/balance)

공식 테스트 환경에서는 개발자 계정에 API 키를 등록하고 등록된 테스트 데이터로 잔액조회를 검증할 수 있습니다. 페이플랜에서 실제 잔고를 표시할 때는 사용자 동의로 조회한 값과 조회 시각을 예상 잔액 옆에 표시합니다. [금융결제원 테스트 시작 안내](https://developers.kftc.or.kr/dev/starter/starter)
